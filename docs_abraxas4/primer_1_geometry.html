DOF — 자유도 (Degree of Freedom)

DOF Degree of Freedom

"어떤 물체가 독립적으로 움직일 수 있는 방향의 수"입니다.

ATM 카드 투입구를 생각해보세요. 카드는 앞뒤로만 밀립니다 → 1-DOF.
책상 위 마우스는 좌우+앞뒤로 움직입니다 → 2-DOF.
공중의 드론은 앞뒤+좌우+위아래 → 3-DOF.
거기에 기울기 3방향(Roll, Pitch, Yaw)까지 더하면 → 6-DOF.

openpilot 적용:
카메라의 pose(자세) 출력이 6-DOF입니다.
pose = [x, y, z, rx, ry, rz]
앞 3개 = 3D 위치 이동량, 뒤 3개 = 3D 회전량.

Roll / Pitch / Yaw

Pitch — 앞뒤 기울기

앞바퀴가 내려가고 뒷바퀴가 올라가는 기울기입니다. 오르막/내리막에서 발생합니다.

  앞 ↓          ↑ 뒤
  ────────────────
  Pitch + (앞이 내려감)

  오르막길: 앞이 올라감 → Pitch -
  내리막길: 앞이 내려감 → Pitch +
openpilot 적용: liveCalibration.rpyCalib[1] = Pitch값.
카메라가 위를 향해 달렸다면 Pitch 보정 필요. calibrationd가 자동 측정합니다.
Roll — 좌우 기울기

왼쪽/오른쪽으로 기우는 각도입니다. 편도로(banked road)나 차체 자체 기울기에서 발생합니다.

  왼쪽 ↓    ↑ 오른쪽
  ──────────────────
    Roll + (왼쪽이 내려감)

  좌회전 구간의 경사진 도로: Roll 발생
openpilot 적용: liveParameters가 도로의 Roll을 추정해
조향 제어 시 좌우 편차를 보정합니다.
Yaw — 좌우 회전 (헤딩)

수직축(하늘-땅 방향)을 중심으로 좌우로 도는 회전입니다. 핸들을 꺾으면 Yaw가 발생합니다.

       ↑ 차 앞
       │
  ←────┼────→   Yaw = 위에서 내려다본 회전
       │
       ↓

  좌회전: Yaw + (반시계)
  우회전: Yaw - (시계)
openpilot 적용: GPS bearing이 Yaw 방향.
나침반에 표시되는 방위각(045°)이 Yaw입니다.
Euler Angle — 오일러 각

Roll, Pitch, Yaw를 각각 숫자 3개로 표현한 것입니다. [roll, pitch, yaw] = [0.01, -0.02, 1.57]처럼.

// C 코드로 비유하자면:
typedef struct {
    float roll;   // 좌우 기울기 (rad)
    float pitch;  // 앞뒤 기울기 (rad)
    float yaw;    // 좌우 회전   (rad)
} EulerAngle;
openpilot 적용: liveCalibration.rpyCalib = [roll, pitch, yaw]
이 3개 숫자로 "카메라가 얼마나 삐뚤게 달렸는지" 표현합니다.

3D 좌표계

World / Camera / Device 좌표계

같은 물체도 어느 기준점에서 보느냐에 따라 좌표가 달라집니다.

  World 좌표계: 지구 기준. GPS 좌표가 여기.
    x = 동쪽, y = 북쪽, z = 위쪽

  Device 좌표계: 차량 기준.
    x = 앞방향, y = 왼쪽, z = 위쪽

  Camera 좌표계: 카메라 렌즈 기준.
    x = 오른쪽, y = 아래쪽, z = 앞방향(광축)
openpilot 적용: 신경망이 출력하는 차선 위치는 Device 좌표계 기준.
lane_lines[0][t][0] = 왼쪽 차선까지 횡방향 거리(m)

Perspective Transform / Warp

Perspective Transform — 원근 변환

카메라는 멀리 있는 것을 작게, 가까운 것을 크게 찍습니다. 이걸 보정해서 "실제 위에서 내려다본 것처럼" 변환하는 것입니다.

  원본 카메라 이미지:         Warp 후 (조감도 시점):
  ┌────────────────┐          ┌────────────────┐
  │  차선이 V자로  │   →      │  차선이 평행선  │
  │  수렴하여 보임 │  3×3     │  으로 보임      │
  │  /────────\   │  행렬    │  │        │     │
  │ /          \  │  변환    │  │        │     │
  └────────────────┘          └────────────────┘

이 변환에 사용하는 수식이 3×3 행렬입니다. 행렬 곱 한 번으로 모든 픽셀 위치가 재계산됩니다.

openpilot 적용:
tfm = 도로 카메라용 3×3 변환 행렬
big_tfm = 광각 카메라용 3×3 변환 행렬
이 행렬은 liveCalibration의 Roll/Pitch/Yaw값에서 계산됩니다.
→ GPU에서 1920×1088 이미지를 128×256으로 warp하여 신경망에 입력합니다.

이미지 포맷: NV12 / YUV

RGB vs YUV

이미지를 표현하는 두 가지 방식입니다.

RGB: 빨강(R), 초록(G), 파랑(B) 각 픽셀에 3바이트. 우리 눈에 친숙한 방식.

YUV: 밝기(Y)와 색상(U,V)을 분리. 카메라/영상 압축에 사용. 카메라 센서가 출력하는 기본 형식.

  픽셀 하나:
  RGB: [R=255, G=128, B=0]  → 주황색
  YUV: [Y=밝기값, U=청록성분, V=적색성분]

  Y (Luma)   = 밝기 정보만. 흑백TV처럼.
  U (Cb)     = 파란색 색차
  V (Cr)     = 빨간색 색차
NV12 포맷

YUV의 한 종류로, 카메라가 실제로 출력하는 형식입니다. 모바일 카메라 표준입니다.

  1920×1088 NV12 메모리 레이아웃:
  ┌────────────────────────────────────────┐
  │  Y 평면  (1920×1088 = 2,088,960 bytes) │  ← 밝기
  ├────────────────────────────────────────┤
  │  UV 평면 (1920×544  = 1,044,480 bytes) │  ← 색상
  │  [U0,V0, U1,V1, U2,V2, ...]           │  ← U와 V가 섞여있음(interleaved)
  └────────────────────────────────────────┘

  총 = 3,133,440 bytes ≈ 3MB (프레임당)
openpilot 적용: Warp Stage에서
1. Y 평면만 추출 (밝기)
2. UV 평면을 U/V로 분리 (deinterleave)
3. 각각 perspective warp → 128×256 크기로 축소
4. 6채널로 합치기: [Y_t0, U_t0, V_t0, Y_t1, U_t1, V_t1]
Deinterleave — 분리

NV12에서 UV 평면은 [U,V,U,V,U,V...] 순으로 섞여 있습니다. 이를 [U,U,U...], [V,V,V...]로 분리하는 것이 deinterleave입니다.

  // C 비유:
  uint8_t uv[4] = {U0, V0, U1, V1};  // interleaved
  uint8_t u[2]  = {U0, U1};           // deinterleaved
  uint8_t v[2]  = {V0, V1};           // deinterleaved

Calibration — 카메라 보정

Calibration — 보정

ATM에서 카드 투입구 위치를 공장 출하 시 맞추는 것과 같습니다. 카메라도 차에 부착할 때마다 각도가 조금씩 다릅니다. 이를 소프트웨어로 자동 측정·보정하는 것이 Calibration입니다.

openpilot 적용 (calibrationd.py):
주행 중 카메라 영상을 분석해 Roll/Pitch/Yaw를 자동 추정.
고속도로 직선 구간 5분 이상 주행하면 "Calibrated" 상태가 됩니다.
결과: liveCalibration.rpyCalib = [0.001, -0.012, 0.003] (라디안)
