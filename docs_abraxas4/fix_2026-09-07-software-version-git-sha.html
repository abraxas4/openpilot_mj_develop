증상 git pull 했는데 버전이 그대로

기기는 main이고 SSH로 HEAD는 GitHub와 같습니다. 설정 → Software만 보면 예전 빌드처럼 보입니다.

SSH / git log
HEAD가 GitHub main과 같음 (예: db36f0262 … 9c72d9f32).
3X Software 화면
Current Version이 커밋 해시가 아니거나, Download가 “up to date, last checked Feb 15”.
manager를 안 재시작하면 계속 예전 SHA
Params GitCommit은 부팅(manager 시작) 때만 갱신.

원인 화면에 쓰는 값이 HEAD가 아님

LastUpdateTime

tizi Software의 Download 줄은 updater가 마지막으로 검사한 시각입니다. 기기 시계/updater 상태가 오래되면 Feb 15처럼 보입니다. 지금 checkout SHA가 아닙니다.

Params GitCommit

manager.py가 시작할 때 build_metadata.openpilot.git_commit을 넣습니다. UI는 그 Params를 읽습니다. git pull만 하면 파일은 새 HEAD인데 Params는 예전 값입니다. 

manager 시작
  params.put("GitCommit", build_metadata.git_commit)
  params.put("GitCommitDate", ...)

git pull          # 디스크 HEAD만 바뀜
Software 화면
  params.get("GitCommit")     ← 여전히 부팅 때 SHA
  params.get("LastUpdateTime") ← updater 검사 시각

수정 live git HEAD

tizi Software는 checkout에서 git을 직접 읽습니다. manager 재시작 없이 pull이 보입니다. 

# openpilot/selfdrive/ui/layouts/settings/software.py
def _live_git():
    git -C BASEDIR rev-parse HEAD          # 12자
    git show -s --format=%cs HEAD          # YYYY-MM-DD
    git rev-parse --abbrev-ref HEAD
    git config --get remote.origin.url
    # 실패 시에만 Params GitCommit / GitBranch / GitRemote
화면 항목내용
Current Version 12자SHA Version / branch YYYY-MM-DD. GitHub 커밋 ID와 비교 가능.
Download (up to date) up to date, {SHA}. LastUpdateTime은 git이 실패할 때만.
Target Branch 공식 updater가 받을 브랜치. 그대로 둠.
Fork Version 12자 SHA + 날짜. 설명: github.com/abraxas4/openpilot_mj_develop (main)
mici (소형 UI) 는 Params를 씀

comma 3X tizi 경로는 live git입니다. mici Software/홈 버전 줄은 아직 UpdaterCurrentDescription / GitCommit 입니다. 3X에서 보는 설정 화면이 tizi 쪽입니다.
