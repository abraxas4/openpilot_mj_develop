2. model 한 번 vs weights 반복 학습

합의된 이해

model (architecture + I/O 꼴) 은 한 번(또는 드물게) 정한다. 그다음 학습 사이클마다 weights 를 업데이트한다. “학습을 다 한 뒤 마지막에만 꼴을 맞춘다”가 아니다 — 틀이 바뀌면 예전 weights 를 replace 에 못 쓴다.

그림 1b. 틀 한 번 + weights 반복
말의미
model 만들기 네트워크 구조·입출력 정의 (코드 model.py 등). 자주 안 바꿈
weights 업데이트 / 한 사이클 train dataset 으로 여러 epoch 돌려 .pt 갱신. 데이터 늘면 다시 돌림
이어서 학습 이전 checkpoint 로드 후 더 train (선택)
처음부터 재학습 같은 틀로 새 초기화 후 dataset 전체로 train (현재 train_real 방식)

3. dataset 이라는 말

dataset

학습·평가에 쓰는 예제 모음 전체를 부르는 말이 맞습니다. 예: “실차 자동 label 로 만든 52,495 sample 모음”.

말이 프로젝트에서
dataset 이미지 + label 이 짝 지어진 전체 자료 (batch_auto 등)
train set / train split 그중 공부용 부분 (manifest_train, ~47k)
val set / validation split 시험용 부분 (manifest_val, ~5k)
sample 한 줄: 이미지 1장 + desired_accel 1개

말해도 되는 예: “같은 dataset 으로 GPU 에서 한 사이클 더 train 한다.” 더 정확히는: “같은 train/val split 으로 다시 training 한다.”

4. 공식 목표

한 문장

openpilot driving model 과 같은 입·출력 꼴(interface / shape) 을 가진 아기 model 을 PC 에서 학습·export 하고, 나중에 3X 에서 replace 했을 때 pipeline 이 돌아가게 한다. comma 수준의 운전 실력 추종은 목표가 아니다.

interface / shape

model 이 받고 내는 데이터의 이름·개수·배열 크기입니다. “플러그에 핀이 몇 개이고 각 핀이 무엇인지”에 해당합니다.

replace

openpilot 이 쓰는 model 파일 자리에 우리 model 을 넣는 것입니다. 성공 기준(현재): 소켓에 맞아 프로세스가 돈다. 잘 달린다가 아님.

아기 model vs 어른 model

같은 커넥터(I/O). weights 품질·운전 능력은 어른(comma)과 아기(우리)로 비유.

포함미포함
I/O 꼴 맞춤, PC training, scp, 전체 자동 label (사람 검수 없음) comma 공식 weights 이어 fine-tune, 도로에서 아기 model 로 안전 완전자율

6. shape · metadata 란? (초보 필수)

tensor

다차원 숫자 상자입니다. 1차원은 숫자 나열, 2차원은 표, 4차원은 이미지 batch 등에 씁니다. model 은 tensor 를 받아서 tensor 를 냅니다.

shape

그 상자의 칸 배치 크기입니다. 예: (1, 12, 128, 256) 은 “batch 1개, 채널 12, 높이 128, 너비 256” 짜리 숫자 블록이라는 뜻입니다. 칸 개수가 안 맞으면 model 은 보통 바로 에러로 죽습니다.

6.1 “입력 shape 을 넣는다”는 말

smoke / inference 때 model 에 실제 카메라 대신 (또는 실제 전처리 결과로) 정해진 크기의 숫자 배열을 만들어 넣는 것을 말합니다.

  • 예: img 자리에 numpy.zeros((1,12,128,256)) 를 넣음
  • 내용은 전부 0이어도 됨 — smoke 목적은 “크기가 맞아 forward 가 되나?”
  • 진짜 학습·주행 때는 0 대신 카메라·로그에서 만든 값이 들어감
그림 S1. 입력 shape → model → 출력 shape

6.2 출력 shape

model 이 내놓는 tensor 의 크기입니다. openpilot driving supercombo 는 출력이 하나이고 shape 이 (1, 2576) 입니다. 즉 “한 번에 숫자 2576개”를 한 줄로 뱉습니다.

그 2576개를 사람이 읽을 이름으로 나누는 표가 output_slices 입니다. 예: plan 은 1576~2566 구간, hidden_state 는 1064~1576 구간.

metadata (메타데이터)

“데이터에 대한 설명 데이터”입니다. 사진 파일의 촬영 시각, MP3 의 곡 제목처럼, model 파일 안에 붙는 부가 정보를 말합니다. openpilot ONNX 에는 특히 output_slices 가 metadata 로 들어 있어 modeld 가 2576칸을 어떻게 자를지 압니다.

구분내용예
model weights 계산에 쓰는 숫자 (본체) CNN 의 필터 값
metadata 해석·버전 안내용 부가 정보 output_slices, model_checkpoint 이름
HTML / JSON 어디에 적혀 있나?
  • 이 절 (shape · metadata 설명)
  • 아래 “I/O 스펙 표” 절 (이름·shape 목록)
  • 기계가 읽는 정본: e2e_learning_lab/artifacts/op_io_spec.json
  • 코드: e2e_learning_lab/src/op_io_spec.py
  • openpilot 쪽 사용: modeld.py 가 metadata 의 slices 로 출력 분해
openpilot driving model in/out 요약
  • In: img, big_img, features_buffer, desire_pulse, traffic_convention, action_t (각각 표의 shape)
  • Out: outputs (1, 2576) → slices 로 plan/차선/lead/hidden…
  • 이 버전 ONNX: 별도 action head 없음 → 가속은 plan 쪽에서 유도

7. openpilot I/O 스펙 표 (우리가 맞추는 핀)

supercombo

openpilot driving model 의 통칭입니다. 카메라 등으로 운전 관련 여러 출력을 한 번에 냅니다. 참조 파일: commaai master 의 driving_supercombo.onnx (lab 에 복사본 사용).

output_slices

길이 2576 짜리 한 줄 출력을 meta, plan, hidden_state 등 이름으로 자르는 구간 표입니다. modeld 가 이 표로 출력을 해석합니다.

Input 이름shape쉬운 설명

7. BabySupercombo 구조 (초보용)

  1. 전방 img (와 약간 big_img) 를 작은 CNN 으로 요약
  2. features_buffer 평균, desire, traffic, action_t 와 이어 붙임 (concatenate)
  3. MLP 로 길이 2576 벡터 출력
  4. hidden_state 구간은 features 요약으로 채워 시간 버퍼가 완전 난수가 아니게 함
  5. 학습 시 label 은 주로 plan 안의 가속 채널에 넣음 (로그 auto label)
supervision (이 단계에서)

2576 칸 전부를 “정답”으로 가르치지는 않습니다. 우리가 가진 자동 label 은 가속 숫자이므로, plan 의 가속 관련 칸에 맞춰 MSE 를 줍니다. 나머지 칸은 꼴을 채우기 위한 자리입니다 (dummy 에 가까움).

6. 꼭 필요한 개념

dataset

학습·평가용 예제 모음(문제집). 예: 이미지 파일들 + labels.csv.

sample

dataset 한 줄. 보통 이미지 1장 + label 1개.

label

맞춰야 할 목표 값. 사람 클릭만이 아님. 로그 자동·프로그램 합성·사람 수정도 모두 label.

supervised learning

입력 X 와 목표 Y 짝으로 weights 를 업데이트하는 학습 방식. 이 lab 이 해당.

training (learning)

데이터로 model weights 를 바꾸는 과정. PC 에서 함.

inference

고정 weights 로 새 입력을 넣어 출력 숫자를 계산. training 과 반대 방향의 실행.

weights

model 내부 파라미터 숫자. .pt, .onnx 등에 저장.

epoch

train dataset 전체를 한 번 다 보는 단위. 첫 train 은 15 epoch 고정 종료.

loss / MSE

예측과 label 이 얼마나 다른지. MSE = Mean Squared Error (평균 제곱 오차). 작을수록 정답에 가깝게 맞추고 있다는 뜻.

synthetic dataset

실제 도로가 아니라 프로그램이 만든 가짜 그림+정답. pipeline 연습용.

10. 전체 자동 batch + 실차 train (CPU)

정책

사람 검수 없이, 복사해 둔 realdata 를 최대한 활용. 정지 화면만 보고 가속/감속을 고치는 것은 비현실적이므로 생략. label 은 qlog carState.vEgo 의 시간 미분(초안)만 사용.

batch

manifest

학습에 쓸 샘플 목록 CSV 입니다. 각 행: segment_id, 이미지 상대경로, desired_accel 등.

11. CUDA / GPU 설치

CUDA

NVIDIA GPU 에서 병렬 연산을 쓰기 위한 플랫폼·드라이버 스택입니다. PyTorch 가 CUDA 빌드이면 training 을 GPU 로 돌릴 수 있습니다.

설치 위치e2e_learning_lab\.venv

pip uninstall -y torch torchvision
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu124

코드는 원래부터 torch.device("cuda" if torch.cuda.is_available() else "cpu") 를 사용. CPU 로 돌았던 이유는 GPU 부재가 아니라 CPU 전용 wheel 때문.
