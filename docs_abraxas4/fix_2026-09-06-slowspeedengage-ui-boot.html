Params 키가 왜 헤더에 있어야 하나

params_keys.h는 C++ 헤더이고, Python params_pyx가 그 목록으로 “허용된 키”를 컴파일합니다. 파일만 고치고 scons를 안 하면 기기에서는 여전히 UNKNOWN일 수 있습니다. 이번엔 토글을 건너뛰게 해서, 재빌드 전에도 화면은 뜨게 했습니다.

후속 Toggles를 열면 KeyError — 커밋 5be1e1b06

첫 수정은 __init__에서 모르는 키를 continue 해서 화면이 뜨게 했습니다. 그런데 Toggles 화면을 열 때 _update_toggles가 정의 목록 전체를 다시 돌며 self._toggles[param]에 접근합니다. 건너뛴 SlowSpeedEngage는 dict에 없으므로 KeyError → UI가 죽고 홈 스피너로 돌아갑니다. 

TogglesLayout.__init__
  for param in _toggle_defs:
    try: get_bool(param)
    except UnknownKeyName: continue   # SlowSpeedEngage 생략

show_event → _update_toggles
  for param in _toggle_defs:           # 생략한 키까지 다시 순회
    self._toggles[param].set_state(...)  ← KeyError

openpilot/selfdrive/ui/layouts/settings/toggles.py 새로고침은 self._toggles.items()만 돈다. 실제로 만든 토글만. LongitudinalPersonality처럼 defs에 없는 항목은 건너뜀.

같은 날 관련 UI

화면이 뜬 뒤 소프트웨어 페이지가 예전 날짜(LastUpdateTime)를 보여 git pull 여부를 알 수 없었습니다. Current Version / Fork Version을 live git HEAD(12자 SHA)로 바꿨고, 설정 슬라이드 때 홈 화면이 한 프레임 비치는 것도 막았습니다. 기록: 3X 소프트웨어 버전 SHA

참고 기기에 남은 prebuilt

복구 중에 전체 scons가 tinygrad device probe에서 SIGKILL(메모리)로 막혀, /data/openpilot/prebuilt를 만들어 부팅 시 전체 재빌드를 건너뛰게 했습니다. 이 파일이 있으면 다음 재부팅도 scons를 안 합니다.

  • 화면은 이미 뜸. Slow Speed Engage 토글이 설정에 없을 수 있음 (키가 아직 바이너리에 없음).
  • 토글을 쓰려면 나중에 rm /data/openpilot/prebuilt 후 재부팅하거나, scons -j1로 params만 빌드.
  • Always On Lateral 키는 원래 있어서 그쪽은 이번 버그와 무관합니다.
