4. capnp Duplicate ID 원인 분석

문제 흐름:

long_mpc.py 실행 (scons subprocess)
│
├── from openpilot.cereal import log
│   └── cereal/__init__.py 실행
│       └── capnp.load(log.capnp, imports=[opendbc_car_path])
│           └── log.capnp: "using Car = import '/car.capnp'"
│               └── car.capnp 로드 → ID 0x8e2af1e708af8b8d 등록 (1회)
│
└── from opendbc.car.interfaces import ACCEL_MIN, ACCEL_MAX
    └── opendbc/car/structs.py 실행
        └── try: from cereal import car
            └── ImportError!
                (scons PYTHONPATH = /data/openpilot:opendbc_repo:...
                 'cereal' 없음. 'openpilot.cereal'만 있음)
            └── except: capnp.load(car.capnp) ← imports 없이
                └── ID 0x8e2af1e708af8b8d 재등록 시도 → "Duplicate ID" ABORT

핵심: cereal vs openpilot.cereal

upstream 머지 후 cereal은 /data/openpilot/openpilot/cereal/로 이동했습니다. scons PYTHONPATH에는 /data/openpilot이 있어 openpilot.cereal로는 접근 가능하지만, 루트에 cereal/가 없으므로 bare cereal은 ImportError.

opendbc의 structs.py는 from cereal import car를 시도하다 실패하고, fallback으로 capnp.load(car.capnp)를 실행해 중복 등록을 유발.

fix 2 opendbc/car/structs.py — openpilot.cereal 먼저 시도

새 openpilot 구조에서 openpilot.cereal을 먼저 시도. 성공하면 이미 로드된 car 스키마를 재사용해 중복 등록 없음.

try:
  from openpilot.cereal import car   # 새 openpilot 패키지 구조 (cereal이 먼저 로드)
except ImportError:
  try:
    from cereal import car           # standalone / 구버전 구조
  except ImportError:
    capnp.remove_import_hook()
    car = capnp.load(BASEDIR + "/car.capnp", imports=[BASEDIR])
