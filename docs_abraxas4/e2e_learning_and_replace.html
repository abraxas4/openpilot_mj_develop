e2e 학습과 model replace

입출력 크기를 맞춰 openpilot driving model 자리에 우리 모델을 넣는 것. 운전 성능을 comma 수준으로 맞추는 것은 목표가 아님. 학습은 PC의 e2e_learning_lab, 실차는 3X의 openpilot_mj_develop.

1. 목표

한 문장

openpilot driving model과 같은 입력 이름·shape, 같은 출력 길이(2576)와 output_slices를 가진 작은 모델을 PC에서 학습·export한다. 나중에 그 파일을 3X modeld가 읽는 자리에 넣었을 때 프로세스가 에러 없이 돌아가는 것이 성공이다. 차선·추종·신호 성능이 comma와 비슷한 것은 성공 조건이 아니다.

한다하지 않는다
입출력 이름·shape를 supercombo ONNX와 맞춤 comma 공식 weights를 이어서 fine-tune
PC에서 dataset · train · ONNX export 3X 위에서 training
로그에서 가속 숫자를 자동 label로 씀 (사람 검수 없음) 도로에서 이 모델로 안전 완전자율
shape가 맞아 forward / parser가 통과하는 smoke “잘 달린다”는 체감 품질

네트워크 구조(architecture)와 입출력 크기는 한 번 정한다. 그다음 사이클은 같은 구조로 weights만 다시 학습한다. 입출력 크기를 바꾸면 예전 weights는 replace에 쓸 수 없다.

3. 용어

말뜻
training데이터로 model 안의 weights를 업데이트하는 과정
inferenceweights를 고정한 채 새 입력으로 출력을 계산. 차가 달릴 때 modeld가 하는 일
weightsmodel 내부 숫자. 파일은 .pt(PyTorch), .onnx(교환용)
tensor / shape다차원 숫자 배열 / 그 크기. 예: (1, 12, 128, 256). 크기가 안 맞으면 즉시 에러
dataset / sample학습·평가용 예제 모음 / 그중 한 개 (보통 이미지 1장 + 목표 값)
label그 입력에 대해 맞춰야 할 목표 값. 사람이 찍을 수도, 차 로그가 만들 수도 있음
supervised learning입력 X와 목표 Y를 짝으로 주고 Y를 맞추게 하는 학습. 이 lab의 train이 이쪽
loss / MSE / epoch오차 / 평균제곱오차 / 데이터 전체를 한 바퀴 학습하는 단위
ONNX모델을 다른 runtime으로 옮기는 파일 형식. Netron으로 입출력 이름을 볼 수 있음
output_slices길이 2576 출력을 plan, hidden_state 등으로 자르는 구간 표. modeld가 이걸 읽음
route / segmentopenpilot 한 번의 주행 묶음 / 약 1분 조각
modeld / modelV2openpilot에서 모델을 돌리는 프로세스 / 그 출력 메시지
replaceopenpilot이 읽는 driving model 파일 자리에 우리 파일을 넣는 것
smoke실제 운전이 아니라, 입력 shape를 넣고 forward가 되는지 확인하는 검사

training은 weights를 바꾸고, inference는 바꾸지 않는다. 3X 주행은 inference다. 학습은 PC에서만 한다.

4. label은 어디서 오나

이 lab은 supervised다. 목표 값(label)이 필요하다. label이 있다고 해서 사람이 frame마다 클릭한다는 뜻은 아니다.

출처내용이 lab
프로그램이 만든 값가짜 이미지와 같이 생성한 숫자synthetic make_dataset (파이프라인 연습)
차 로그속도, 가속도, 조향 등 이미 기록된 숫자실차 학습의 기본. qlog에서 가속을 뽑아 label
사람 주석클릭·박스·클래스 이름쓰지 않음

합의된 작업 방식:

  1. 로그로 자동 label 생성 (예: vEgo 미분)
  2. 정지 화면을 보고 가속/감속을 고치지 않음
  3. 있는 qcamera+qlog segment를 batch로 전부 처리한 뒤 train

5. openpilot 입출력

참조는 comma driving supercombo ONNX. 정본 표는 lab의 src/op_io_spec.py → artifacts/op_io_spec.json. 내부 weights가 왜 그 숫자를 내는지는 이 표로 설명되지 않는다. 맞추는 것은 입출력 크기와 이름이다.

입력 이름shape의미
img(1, 12, 128, 256)전방 비전 (여러 frame을 채널로 묶음)
big_img(1, 12, 128, 256)wide 비전
features_buffer(1, 24, 512)과거 feature
desire_pulse(1, 25, 8)차로 변경 등 의도
traffic_convention(1, 2)좌핸/우핸
action_t(1, 2)제어 delay 시간
출력shape의미
outputs(1, 2576)한 벡터. modeld가 output_slices로 자름
slices 예구간별meta 0:55, hidden_state 1064:1576, plan 1576:2566
action head—이 ONNX 버전에는 없음. 가속은 plan 쪽에서 유도

smoke에서는 카메라 대신 numpy.zeros((1,12,128,256))처럼 정해진 크기의 배열만 넣어도 된다. 목적은 “크기가 맞아 forward가 되나”이다.

6. TinyAccelNet과 BabySupercombo

TinyAccelNetBabySupercombo
입력이미지 1장supercombo과 같은 입력 6종
출력숫자 1개 (가속)(1, 2576) + output_slices
용도파이프라인 연습. replace 불가입출력 크기를 맞춰 replace 후보를 만드는 단계
코드src/model.pysrc/baby_supercombo.py

BabySupercombo이 하는 일:

  1. 전방 img(와 약간 big_img)를 작은 CNN으로 요약
  2. features_buffer 평균, desire, traffic, action_t와 이어 붙임
  3. MLP로 길이 2576 벡터 출력
  4. 학습 때 2576칸 전부를 가르치지 않음. 로그 자동 label이 있는 plan의 가속 채널에만 MSE
  5. 나머지 칸은 크기를 채우기 위한 자리

9. 안전

하지 말 것
  • 이 모델로 일반 도로에서 engage하지 말 것. smoke PASS는 “크기가 맞다”이지 “운전이 된다”가 아니다.
  • replace 1차는 PC replay 또는 바퀴가 구르지 않는 환경을 우선할 것.
  • synthetic 빨간/초록 blob 규칙을 신호등 인식으로 착각하지 말 것.
  • panda safety가 잘못된 model 출력을 전부 막아주지는 않는다.
