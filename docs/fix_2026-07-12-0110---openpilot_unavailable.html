📡 참고사항 — "publish / subscribe" 란? 프로세스 간 통신 구조

openpilot은 여러 프로세스(card, selfdrived, modeld 등)가 동시에 독립 실행됩니다. 이 프로세스들이 서로 데이터를 주고받는 방식이 pub-sub(발행-구독)입니다.

파일 기반이 아닙니다 — 공유 메모리(shared memory) 기반

  • Publisher(발행자): 데이터를 공유 메모리의 토픽에 씀
  • Subscriber(구독자): 그 토픽을 읽음. RAM이므로 마이크로초 단위 지연
  • 기반 기술: msgq (shared memory 큐) + cereal (Cap'n Proto 직렬화)
임베디드 비유 (ATM 기준):
  ISR → 링버퍼 write → 메인루프 read  (프로세스 내부)

openpilot (프로세스 간):
  card.py       → msgq 공유메모리에 carParams write  (publish)
  selfdrived    → 같은 공유메모리에서 carParams read  (subscribe)
  rlog.zst에도 기록됨 → 나중에 분석 가능

→ card.py가 crash하면: carParams 토픽이 게시되지 않음 → selfdrived가 차 인식 못함 → "openpilot unavailable". rlog에도 carParams 메시지 타입 자체가 없게 됨.

3. 하드웨어 체크리스트

확인 항목정상문제 시
OBD-II 하네스 연결 차량 대시보드 아래 OBD 포트에 단단히 체결 느슨하거나 빠짐 → 재연결

시동 상태 ENGINE ON (ACC 아님) ACC만 켜면 ignitionLine = False
harnessStatus connected notConnected = 하네스 물리적 미연결

💥 STEP 4 — card.py crash 원인 추출
4
rlog의 errorLogMessage 타입에서 card daemon의 Traceback을 추출합니다.
python3 -c "
import json
from openpilot.tools.lib.logreader import LogReader

RLOG = '/data/media/0/realdata/000001db--caae7c20d0--0/rlog.zst'
lr = LogReader(RLOG)

for msg in lr:
    if msg.which() != 'errorLogMessage':
        continue
    try:
        d = json.loads(msg.errorLogMessage)
    except:
        continue
    daemon = d.get('ctx', {}).get('daemon', '')
    m = str(d.get('msg', ''))
    exc = d.get('exc_info', '')
    # card daemon의 에러/crash만 출력
    if 'card' in daemon and ('crash' in m or exc):
        print(f'[{daemon}] {m}')
        if exc:
            print(exc[:800])
"
